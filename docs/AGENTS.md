# 文档规范

本文件只规定文档的组织与维护方式。开发流程、代码风格、发布与 Git 提交规范统一见[根目录 AGENTS.md](../AGENTS.md)。

## 目录分工

| 位置 | 保存什么 | 维护方式 |
| --- | --- | --- |
| [PROTOCOL.md](PROTOCOL.md) / [PROTOCOL.zh-CN.md](PROTOCOL.zh-CN.md) | wire 规格：字段定义、编码、发射规则、v1 边界；代码内 `§N` 引用的锚点 | 英中两两对应修改；演进只增版本节，不改写旧版语义 |
| [COMPATIBILITY.md](COMPATIBILITY.md) / [COMPATIBILITY.zh-CN.md](COMPATIBILITY.zh-CN.md) | 实测钩子时序事实与已知限制（v1） | 升级 langchain / deepagents 或发现新时序事实后更新，注明验证环境与版本 |
| [design/](design/) | 开发需求的设计文档：范围、接口、兼容性影响，以及设计的演进与修订 | 只增不删；新设计引用原设计并说明补充或替代范围 |
| [tasks/](tasks/) | 开发需求的任务验证文档：目标、实现路径、验收标准，以及实施中的进展、调整与验证结果 | 一项任务一个文件，持续更新；多版开发用版本后缀递增并引用前版 |

## 文档维护

- **开发需求建档**：按根目录开发流程第 1 条执行——设计文档落 `design/`，任务文档落 `tasks/`；任务文档须包含验收标准与验证记录（验证命令、结果摘要、剩余限制），文档名用英文 `kebab-case` 描述性命名。
- **双语对应**：`PROTOCOL` 与 `COMPATIBILITY` 改任一语言版本必须同步另一版，顶部语言切换行保持；README 双语同理。内容两两对应，不出现单侧新增章节。
- **design/ 只增不删**：已有设计不覆盖、不删除；设计被替代时在新文档中引用原文并说明范围。
- **tasks/ 一任务一文件**：在同一文件内维护进展、调整与验证结果，不拆成 plan / progress / result 多个文档；结果如实记录，未执行的验证标注待验收。
- 小 bug 和局部改动不强制建 design / task 文档，是否建档按根目录开发流程第 1、3 条判断。
- 临时验证脚本、抓包原始输出、试运行日志不入 `docs/`；需要长期化的证据脱敏后保存（不出现明文凭据、真实网关地址与机器路径）。
- 默认使用中文撰写设计与任务文档，文件为 UTF-8、LF，并以换行结束。修改后自查路径、链接、`§N` 锚点与示例可运行。
